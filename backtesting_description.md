# CryptoPilot Backtesting Engine Description

This document details the functionality and execution flow of the CryptoPilot backtesting simulator, based exclusively on the `backtesting_lms.py` implementation.

## Overview
The Backtesting Engine (`BacktestEngine`) is a historical simulator designed to replay historical cryptocurrency market data, triggering the Analyst and Risk Manager agents step-by-step to evaluate their trading decisions over past market conditions. It simulates portfolio state, executes trades, calculates performance metrics, and generates visual reports.

## Core Components

1. **State Management**:
   - Tracks `initial_balance` (defaults to \$100,000 as configured in the main execution block) and current `balance`.
   - Maintains an active `portfolio` (list of open trades).
   - Records `trade_history` for closed positions.
   - Logs an `equity_curve` to track balance fluctuations over time.

2. **Agent Integration**:
   - Integrates the `TradingKnowledgeBase`, `AnalystAgent`, and `RiskManagerAgent`.
   - Re-evaluates AI strategy at every step as if the system were running live.

3. **LLM Caching System**:
   - To accelerate repeated simulation runs and minimize API costs, the engine implements a local JSON cache (`tests/llm_cache.json`).
   - Before requesting a new AI analysis, it checks if an `AnalystSignal` and `RiskAssessment` for the current timestamp already exist in the cache. 
   - If an API error occurs during the LLM request, the simulator safely pauses and resumes, preventing data loss.

4. **Logging System**:
   - Writes detailed execution logs to `tests/logs/`.
   - Generates a general step-by-step state log and a separate detailed trade log tracking R:R ratios, entry/exit conditions, and PnL.

## Simulation Execution Flow

The simulation is executed via the `run()` method, which iterates over a Pandas DataFrame of historical market data.

1. **Initialization**:
   - Begins execution starting at a sliding `window` of 200 rows to ensure enough historical data is available for indicator calculations (e.g., 200-day moving averages).

2. **Step-by-Step Loop**:
   For each historical candle (step):
   - **Equity Tracking**: Records the current timestamp, balance, and price.
   - **Environment Context Generation**: Builds an execution namespace (`locals_dict`) containing the current row's indicators (RSI, Bollinger Bands, etc.), injected previous-step indicators (e.g., `rsi_prev`), and computed Donchian Channel extremes (10, 20, 50, and 55-day highs and lows).
   - **Exit Evaluation**: Iterates over all open trades in the `portfolio`:
     - Checks if the current candle's `high` hits the trade's `target` (Take Profit).
     - Checks if the current candle's `low` hits the trade's `stop_loss`.
     - Uses a custom Abstract Syntax Tree (AST) safe parser (`_evaluate_condition()`) to dynamically evaluate string-based exit conditions generated by the LLM (e.g., "rsi > 70 and price < bb_lower"). 
     - If any exit is triggered, the position is closed, PnL is added to the balance, and the exit is logged.
   - **Market Context Gathering**: Retrieves a structured market context packet using `MarketDataProcessor`.
   - **Agent Decision**:
     - Uses the caching system or invokes the `AnalystAgent` and `RiskManagerAgent` to process the context packet and generate a trading verdict.
   - **Entry Execution**:
     - If the `RiskManagerAgent` outputs a "BUY" signal, the engine attempts to open a position.
     - The `position_size` is constrained by the current available `balance`.
     - The trade is added to the `portfolio` and the `balance` is reduced by the position size. (Note: The simulation is designed to process one position at a time).

3. **End of Simulation**:
   - Automatically closes any remaining open positions at the final available price to realize all PnL and provide accurate end-of-test metrics.

## Condition Evaluation Engine
The backtester includes a custom, secure condition evaluator (`_safe_eval_node`) that parses LLM-generated conditional strings into an AST. 
- It prevents arbitrary code execution by strictly restricting operations to basic arithmetic (+, -, *, /), comparisons (<, >, ==, !=), and boolean logic (and, or, not).
- It auto-fixes common LLM syntax hallucinations (e.g., translating "10-day high" to "high_10").

## Metrics and Reporting

After the simulation loop completes, the engine generates comprehensive reports:

1. **Performance Metrics**:
   - Calculates Initial/Final Balance, Net Profit, Total ROI %, Total Trades, Win Rate %, and Profit Factor.
   - Outputs these metrics to the console and exports them to `tests/metrics.csv`.

2. **Visual Graphs (Plotly)**:
   - **Equity Curve** (`tests/equity_curve.html` & `.png`): A line chart visualizing the account balance over the course of the simulation.
   - **Trade Chart** (`tests/trade_chart.html` & `.png`): A candlestick chart showing the asset's price action overlaid with execution markers:
     - Green triangle-up for Entries.
     - Green/Red triangle-down for Exits, depending on profitability.
